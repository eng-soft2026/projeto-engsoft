- Issue #133 (FE-02, API client, error mapping and form pattern, doc 10): dependencies `react-hook-form` 7.91.0 and `@hookform/resolvers` 5.9.2 (doc 02). Forms post with `fetch` to `/api` (see the decisions log). Usage:
    - `apiFetch(path, { method, body, signal })` (`src/lib/api-client.js`): only same-origin paths (`/api/...`; an absolute or `//` URL throws `TypeError`), `credentials: "same-origin"`, `body` sent as JSON, no token in JS. Returns `data` of the success envelope and otherwise throws `ApiError { code, message, status }`: the envelope code and message, `NETWORK_ERROR` with status 0 when the request fails (an `AbortError` is rethrown unchanged), `INTERNAL_ERROR` with the real status when the answer is not an envelope. A 401 `UNAUTHORIZED` calls `redirectToLogin` (`/login?callbackUrl=<current page>`, nothing when already on `/login`) and still throws; a 401 `INVALID_CREDENTIALS` does not redirect. `createApiClient({ fetchImpl, onUnauthorized })` builds one with injected dependencies for tests.
    - `resolveErrorMessage(error)` (`src/lib/error-messages.js`): the server message first; `ERROR_MESSAGES` (every code of doc 10 plus `NETWORK_ERROR`) only when the message is empty; `DEFAULT_ERROR_MESSAGE` for an unknown code or an error that is not an `ApiError` (never the raw JS message).
    - `useApiForm({ schema, defaultValues, submit, onSuccess, successMessage, fieldErrorCodes })` (`src/hooks/use-api-form.js`) returns `{ form, onSubmit, formError, isSubmitting }`. `form` is the `react-hook-form` instance with `zodResolver(schema)` (reuse the schemas of `src/schemas/`; `submit` receives the parsed values, transforms applied). Field errors come from Zod on the client; a server code listed in `fieldErrorCodes` (`{ USER_ALREADY_EXISTS: "email" }`) goes to that field and gets the focus; any other error goes to `formError` plus `toast.error`. `successMessage` shows `toast.success`, then `onSuccess(data, values)` runs.
